Tracks #3933 under #4027. Syntax-level literal decoding remains exact; all
normalized semantic literals now pass through the primitive owner. Its singleton

## Correctness and coverage

Executed public CLI and real stdio MCP regressions for quoted strings, cooked
no-substitution templates, equivalent concatenation and a small exact control.
Before correction, both direct forms retained a 200,000-unit normalized literal;
addition already reported the byte limit. After correction, all three oversized
forms return `resource-limit` unknowns and partial application coverage with
`javascript_semantic_primitive_bytes = 1048576`. The small value stays exact.
CLI/MCP Evidence IDs match and the source file/digest remain unchanged. This
establishes the documented conservative bound, not an observed OOM or actual
ASCII JSON size above 1 MiB.

Domain boundary checks admit 174,762 UTF-16 code units (1,048,574 estimated bytes)
and reject one more (1,048,578 estimated bytes). The source representation does
not change that outcome. Initial domain control assertions mistakenly required
an explicit empty optional limit array; after correcting omission handling,
both over-bound cases reproduced the defect. They are recorded separately.

Executed: **55 focused tests** across domain, public CLI/MCP and filesystem
projection; **923 semantic tests** in 36 files. The existing large-wire regression
now uses 16 independently admitted literals, asserts at least the former total
UTF-16 payload, retains every value, distinct numeric/string identities, empty
strings, source provenance and retained tracing. Its original oversized single
normalized value violated the documented allocation policy. The aggregate case
passed before/after and passed again after extracting its fixture construction
to satisfy function-size lint. Inputs are regenerated by the tests.
